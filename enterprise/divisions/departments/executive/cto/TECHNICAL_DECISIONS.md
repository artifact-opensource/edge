## ADR-001: Enterprise Update Engine — Python + Shell Wrappers

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** CEO requires single-command enterprise refresh. Existing DB sync was Python-only.  
**Decision:** Core engine in Python (`scripts/update_engine.py`), thin Bash/PowerShell wrappers at repo root.  
**Rationale:** Python already used for DB sync; shell wrappers provide OS-native entry points. No new runtime dependencies.  
**Consequences:** Windows users need Python 3 on PATH. Cross-platform maintained via dual wrappers.

## ADR-002: Root README Auto-Generation

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** Root README was a marketing page that drifted from actual repo structure.  
**Decision:** README.md is fully auto-generated by the update engine on each `--apply` run.  
**Rationale:** Eliminates drift permanently. Marketing content lives in `ARTIFACT-VIRTUAL.md`.  
**Consequences:** Manual README edits are overwritten. Footer warns contributors. Structure changes are reflected automatically.

## ADR-003: Pure CSS/HTML Dashboard (No Chart.js CDN)

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** CEO eagle-eye dashboard needed charts/graphs. Initial implementation used Chart.js CDN.  
**Decision:** Replaced with pure CSS bar charts, sparklines, and progress bars. Zero external dependencies.  
**Rationale:** CDN blocked in secure environments. Self-contained HTML works offline, on any device, with no network.  
**Consequences:** Less interactive than Chart.js. Sufficient for current KPI display needs.

## ADR-004: Monolithic Append-Only Changelog

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** Need enterprise-level change tracking separate from git history.  
**Decision:** Single file `changelog/CHANGELOG.md` with semver entries. Append-only — never truncate or modify existing entries.  
**Rationale:** Audit trail requirement. Git log tracks code changes; changelog tracks enterprise-level changes (data refreshes, drift detection, CSV rebuilds).  
**Consequences:** File grows indefinitely. Acceptable: enterprise changes are infrequent (daily at most).

## ADR-005: Dry-Run Default for Update Engine

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** Destructive operations (README overwrite, DB sync) need safety.  
**Decision:** Engine defaults to dry-run mode. `--apply` flag required to commit changes.  
**Rationale:** Prevents accidental overwrites. Preview-before-apply matches CEO requirement for change confirmation.  
**Consequences:** Users must explicitly opt-in to changes. Two-step workflow for daily use.

---

## ADR-006: CSV Formula Removal

**Date:** 2026-02-11  
**Status:** Accepted  
**Context:** Department CSVs contained Excel-style formulas (`=SUM()`, `=IF()`) that don't compute in plain CSV.  
**Decision:** Replace all formulas with pre-computed values. CSVs are data snapshots, not spreadsheets.  
**Rationale:** CSVs are consumed by Python scripts, HTML visualizers, and the update engine — none of which evaluate formulas.  
**Consequences:** Department leads updating CSVs must input computed values directly. No formula dependency chains.

## ADR-007: In-House CRM (No Salesforce/HubSpot)

**Date:** 2026-02-11  
**Status:** Proposed (pending CTO-002 implementation)  
**Context:** CEO requires customer request pipeline. Third-party CRM evaluated and rejected.  
**Decision:** Build custom CRM pipeline integrated into the enterprise repository.  
**Rationale:**  
1. Proprietary requirement (confidential business operations)  
2. Integration with existing JSON database system  
3. Zero licensing cost  
4. Full control over data residency (Pakistan SECP compliance)  
5. CEO directive: "we are extremely capable of building our own software"  
**Consequences:** Higher initial development effort (~4 weeks). Full customization capability. No vendor lock-in.
