### HEKTOR Segfault Fix (~12:00–12:30 EST)
**Root cause found:** `create_gold_standard_db()` calls `init()` internally. When user calls `db.init()` again, `VectorStore::init()` finds existing `vectors.bin` and reopens it **read-only** via `open_read()`. Then `add_vector()` writes to read-only mmap → SIGSEGV.

**Debug trail:**
- Added fprintf instrumentation through entire call chain
- Narrowed crash to `memcpy` in `VectorStore::add()` — dest pointer was valid but mmap was read-only
- `dmesg` confirmed: `error 7` = write to present page with insufficient permissions
- Key insight: source read worked (`src[0]=1.0`), but `slot_ptr[0] = 0.0f` segfaulted → write protection

**Fix (PR #42):**
1. `VectorDatabase::init()` returns early if `ready_` is true (idempotent)
2. Added `MemoryMappedFile::open_readwrite()` — opens existing file with `PROT_READ|PROT_WRITE` / `MAP_SHARED` without truncation
3. `VectorStore::init()` uses `open_readwrite()` for existing files instead of `open_read()`

PR: https://github.com/amuzetnoM/hektor/pull/42
Branch: `fix/double-init-segfault`
